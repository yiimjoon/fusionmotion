# BQ Fusion 스타일 플레이북

## 목적과 읽는 순서

사용자의 편집 방식을 다음 제작에서 재사용하기 위한 지침이다. 모델 자체를 재학습한 것이 아니다. 이 저장소에 접근한 에이전트가 AGENTS.md → 이 문서 → FUSION_MOTION_KO.md → 근거 JSON을 읽어 맥락을 복원한다. 새 영상의 대본·어셋·타이밍이 없으면 과거 장면을 그대로 복제하지 않는다.

분석일: 2026-09-08. Resolve 21.1의 현재 열린 컴포지션을 읽기 전용으로 조사했다. 현재 프레임 303에서 값, 전체 연결, BezierSpline 키를 읽었다. 원본 미디어·로컬 경로·대사·이미지는 저장소에 넣지 않았다. 이 문서는 한 컴포지션의 관찰과 기존 제작 규칙의 결합이며, 사용자의 모든 작품에 대한 보편 법칙이 아니다. 이번 조사에서는 렌더·청취·뷰어 시각 검증을 하지 않았다.

## 한 문장으로 요약한 구성 성향

**오브젝트별 콜라주를 쌓고, 개별 움직임과 합성 묶음의 움직임을 분리해 조합하는 편집 가능한 2D 합성.** 이는 아래 구조에서 도출한 해석이다. 촬영본/AI 영상 구분이나 특정 동작과 SFX의 정확한 싱크는 그래프만으로 확정하지 않는다.

사용자 정정(2026-09-08): **마스크 리빌과 모자이크 변화는 가끔 쓰는 선택적 기법이지 스타일의 핵심이 아니다.** 이번 샘플에 등장한 빈도를 사용자 전체 스타일의 중요도로 일반화하지 않는다. 다음 제작에서 기본 삽입하거나 필수 컨트롤로 노출하지 말고, 장면의 필요나 명시적인 요청이 있을 때만 검토한다. 피사체 분리용 마스크와 전환 연출용 마스크 리빌도 구분한다.

## 실제 관찰

174개 API 항목: MediaIn 22, Transform 28, Merge 31, MultiMerge 1, Background 11, PolylineMask 10, RectangleMask 3, EllipseMask 3, MosaicBlur 7, ChromaKeyer 3, 3DKeyer 1, TimeSpeed 1, StopMotion 1, PipeRouter 2, PolyPath 11, BezierSpline 28, AudioDisplay 10. 보이는 합성 노드와 내부 모디파이어를 구분한다. AudioDisplay 10개를 SFX 10개로 해석하지 않는다.

MediaOut1에서 입력 연결을 역추적하면 174개 모두 도달한다. 따라서 이 샘플에 구조적으로 완전히 분리된 노드는 없었다. 연결되어 있다는 것이 매 프레임 모두 계산되거나 화면에 모두 보인다는 뜻은 아니다. 입력의 GetKeyFrames()는 이미지 유효 구간도 반환할 수 있으므로 실제 애니메이션 분석에는 BezierSpline.GetKeyFrames()를 사용했다. 조회된 입력에 simple expression은 없었고, Path/Spline 연결이 핵심이었다. 이것을 모든 프로젝트에서 수식을 싫어한다는 뜻으로 일반화하지 않는다.

## 다음 영상 제작 절차

1. 대본과 컷별 목적부터 읽는다. 강조할 대상, 진입/리빌/정착/퇴장 시점, 필요한 어셋과 SFX 후보를 짧게 작성한다. 타이밍 근거가 없으면 임의 싱크를 사실처럼 기록하지 않는다.
2. 현재 프로젝트/타임라인/컴포지션을 다시 조회한다. 선택한 대상, 해상도, 픽셀 종횡비, 타임라인 FPS와 Fusion FPS, Global/Render 범위, 소스 핸들을 확인한다. 이번 분석의 303프레임이나 특정 프로젝트를 하드코딩하지 않는다.
3. 원본 스냅샷 후 해당 작업이 소유할 새 노드만 만든다. 자동 연결을 피하고 입력 ID를 확인해 연결한다. 기존 노드나 이름 없는 Transform을 임의 삭제하지 않는다.
4. 어셋 → 키/마스크 → Layout Transform → Local Motion → Local Merge를 만든다. 이후 필요에 따라 Group Move → Rotate → Exit → Global Pan/Zoom으로 분리한다. 순서는 장면별로 정하고 overscan을 확보한다.
5. 진입 액센트, 읽을 수 있는 홀드, 다음 화면으로 넘어가는 동작을 구분한다. Center는 Path, 시간 진행은 편집 가능한 Spline을 우선 검토한다. 필요한 곳에만 수식을 쓰고 사용자 편집 지점을 남긴다.
6. 고정 절대 프레임을 복사하지 않는다. 아래 시간 변환 규칙으로 샷 길이에 맞추되, 빠른 액센트가 무조건 비례 늘어나지 않게 별도 길이를 둔다.
7. Stop Motion은 합성 질감이 필요한 경우 최종단에 둔다. 효과 종료 뒤에도 최종 화면을 클립 끝까지 유지한다. TimeSpeed는 소스 범위/핸들/마지막 출력 프레임을 따로 검증한다. 샘플의 Speed=2.03을 복사하지 않는다.
8. FG 분기는 소비 Merge 위, 마스크는 아래, 최종 합성 줄기는 왼쪽→오른쪽. 위치를 격자로만 맞추지 말고 선 교차부터 줄인다. 좌우 간격만 요청하면 Y/연결/파라미터는 건드리지 않는다.
9. SFX는 실제 화면 행동과 연결한다. 기존 피드백상 셔터·기어·Swoosh·오토바이·레이싱카·자동차를 구별하고, 같은 종류의 반복과 추가 레이어도 놓치지 않는다. 단지 빈 공간이 있다는 이유로 효과음을 넣지 않는다.
10. 노드/연결/키 값 검증 후 사용자에게 확인 지점을 알려준다. 프록시 변경·프리뷰 렌더는 자동 실행하지 않는다. 시각 확인이나 렌더가 없으면 그 상태를 명시한다.

## 재사용할 시간/컨트롤 설계

추천 공개 컨트롤: StartFrame, EntryFrames, HoldFrames, ExitFrames, TravelX/Y, Scale, Angle, RevealFrames, MosaicStart/End, StopMotionEnabled, FrameRepeat. 사용 목적에 필요한 것만 노출하고 컬러는 컬러피커를 사용한다. 자동 opacity는 몰래 넣지 않는다. 기존 CodexTypo Follower는 요청 없이 제거하지 않는다.

정규화 키 (u,v)를 실제 프레임으로 만들 때: f = start + round(u * durationFrames). 시작/끝 프레임이 모두 포함되는 N개 샘플 구간이면 durationFrames=N-1이다. LH/RH의 시간 오프셋도 같은 비율로 변환한다. 런타임 SetKeyFrames의 핸들은 상대 좌표이며 저장된 setting의 절대 좌표와 혼용하지 않는다. 시작·중간·끝·홀드 후·최종 프레임을 수치 검사한다. duration=0과 짧은 클립에서 키 중복을 처리한다.

이는 **향후 구현 제안**이며 이번에 범용 자동 생성기를 완성하거나 새 매크로를 렌더 검증한 것은 아니다. 이번 그래프는 수동 키 기반이므로 '완전 절차적이었다'고 기록하지 않는다.

## 검증과 갱신

- 확인됨: 호스트 입력 조회, 전체 연결 역추적, 실제 스플라인 키, StopMotion/TimeSpeed 샘플 값.
- 해석: 콜라주와 개별/그룹 움직임을 분리하는 구성 성향.
- 사용자 확인: 마스크 리빌·모자이크 변화는 가끔 사용하는 보조 기법이며 핵심 스타일이 아니다.
- 미확인: 완성 영상의 화면 내용, 속도 체감, SFX 싱크, 각 소스의 촬영/AI 여부, 성능 병목, 새 장면 재현 품질.
- 사용자 승인이나 다음 작품의 반례가 생기면 해당 규칙의 근거와 범위를 갱신한다. 무조건 적용할 취향으로 고정하지 않는다.
