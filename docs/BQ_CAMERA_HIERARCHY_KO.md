# BQ 로컬 모션과 글로벌 카메라: 두 번째 컴포지션 분석

2026-09-08, Resolve 21.1에서 현재 열린 두 번째 컴포지션을 읽기 전용으로 조사했다. 샘플 프레임은 63이다. 연결·Spline 키·TimeSpeed 값을 조회했으며, 프레임 이동·노드 수정·렌더는 하지 않았다. 수치는 해당 장면의 사례이지 다음 장면의 기본값이 아니다.

## 사용자 확인이 있는 핵심

**각 요소에 로컬 Transform을 걸어 개별 배치와 움직임을 만들고, 합성 후 글로벌 Transform으로 장면 전체를 움직여 카메라처럼 연출한다.** 사용자가 직접 설명한 작업 방식이며 두 컴포지션의 구조에서도 반복 확인했다.

글로벌은 노드 이름이나 화면상의 위치가 아니라 입력에 포함된 장면 범위로 판단한다. 모든 최종 레이어가 반드시 같은 카메라를 통과하는 것은 아니다. 회전 상쇄 수식은 사용자 정정에 따라 스타일 패턴과 재사용 규칙에서 제외한다. 마스크 리빌·모자이크 역시 선택적 보조 기법이다.

## 두 샘플의 비교

| 항목 | 첫 컴포지션 | 두 번째 컴포지션 | 해석 |
|---|---:|---:|---|
| 전체 API 항목 | 174 | 274 | 내부 모디파이어·매크로도 포함하므로 보이는 노드 수와 다르다. |
| Transform | 28 | 40 | 개별 요소와 합성 결과의 변환을 나눠 구성한다. |
| Merge / MultiMerge | 31 / 1 | 22 / 2 | 요소를 조립하고 합성 단위로 제어하는 구조가 반복된다. |
| MediaIn | 22 | 9 | 이번 샘플은 외부 미디어 입력 비중이 더 낮다. |
| TextPlus / Follower | 0 / 0 | 26 / 16 | 이번에는 타이포그래피 기반 구성도 같은 계층 구조로 처리한다. |
| TimeSpeed | 1 | 18 | 이번에는 애니메이션의 등장 시점을 외부에서 조절하는 사례가 뚜렷하다. |
| MosaicBlur | 7 | 0 | 모자이크가 스타일의 필수 조건이 아님을 보여준다. |
| 최종 StopMotion | 1 | 1 | 두 샘플 모두 frameRepeat=2, frameRepeatVar=0. 모든 장르에 강제하지 않는다. |

## 실제 카메라 계층

```text
요소 / Text+ / 도형
  → 로컬 애니메이션
  → 필요한 요소의 TimeSpeed(등장 시점 조정)
  → 로컬 배치 Transform
  → Merge / MultiMerge로 장면 조립
  → Merge9
  → Transform2 → Transform14 → Transform5 → Transform10
  → Transform15 → Transform16 → Transform17 → Transform18
  → Merge2 → Merge11 → Merge12
  → StopMotion1 → MediaOut1
```

이는 대표 흐름이며 모든 로컬 분기가 TimeSpeed를 거치는 것은 아니다. Merge2에는 Merge10이 Foreground로, Merge11에는 MediaIn8이, Merge12에는 MediaIn7이 추가된다. 이 입력들은 위 글로벌 Transform 체인 뒤에서 합쳐지므로 그 체인의 영향을 받지 않는다. 화면 고정 레이어가 필요할 때 활용할 수 있는 구조지만, 해당 미디어의 실제 화면 역할은 시각 확인 전까지 단정하지 않는다.

### 글로벌 체인의 역할과 시간

| 노드 | 조회된 값/키 | 해석과 주의 |
|---|---|---|
| Transform2 | Size 0.252, Pivot (0.542, 0.7982), 프레임 63 | 조립된 큰 레이아웃을 기본 구도에 배치하는 단계로 해석 가능. |
| Transform14 | Size 1→1.048, f0→71 | 초반의 작은 스케일 변화. |
| Transform5 | Angle 90→0, f68→114; Size 0.761@63 | 회전 단계. 이 노드에는 고정 크기 보정도 있어 '한 노드는 한 속성만'으로 단정하면 안 된다. |
| Transform10 | Size 1→2.08, f68→121 | 회전과 거의 같은 시점에 확대가 겹친다. |
| Transform15 | Center←Path1; Displacement 0→1, f123→301 | 긴 구간의 화면 이동. 정확한 시선 대상은 화면 확인 필요. |
| Transform16 | Size 1→0.663, f264→323 | 이동 후반과 겹치는 축소. |
| Transform17 | Center (0.5,0.5), Size 1, Angle 0@63 | 조회 시점에서는 중립값. 이름만 보고 추가 카메라 동작으로 꾸며내거나 불필요하다고 삭제하지 않는다. |
| Transform18 | Size 1→1.483, f318→365 | 축소 종료와 일부 겹치는 재확대. |

중요한 건 '회전→확대→이동'이라는 고정 순서가 아니다. **합성 순서와 애니메이션의 발생 시간은 서로 다른 축**이다. 회전과 확대는 같은 f68에서 시작하며, 이동과 축소도 겹친다. 다음 제작에서는 장면 목적에 따라 카메라 동작을 설계하되, 각 단계가 따로 수정되도록 노드를 나눈다.

### 확대 중심도 장면별로 다르다

프레임 63에서 Transform10 Pivot=(0.542,0.829), Transform16=(0.5,-0.047), Transform18=(0.5,0.97)로 서로 다르다. 단순히 Size만 바꾸는 것이 아니라 확대·축소의 기준점을 따로 설정한 구조다. 다만 이 좌표를 다음 영상에 그대로 가져가거나 특정 피사체를 겨냥했다고 추정하지 않는다. 새 구도에서 목표 지점을 정하고 Pivot과 Center를 함께 검증한다.

## 반복 요소: 애니메이션과 배치 시간의 분리

이번에는 TypotestPreset / BQColorRevealText 계열 MacroOperator가 16개, Follower가 16개다. 여러 Follower의 기본 이동·불투명도 키가 f0→16으로 반복되고, 도형 스케일 애니메이션도 f0 Size=0 → f36 Size=0.2로 반복된다.

그 뒤 TimeSpeed의 Speed는 18개 중 17개가 1이다. 즉 이 샘플에서는 대부분 배속보다 **Delay를 통한 시간 배치**에 사용한다. 남은 TimeSpeed3만 Speed=1.42, Delay=15.6이다.

- 도형 분기: Delay 12, 22, 30, 36, 34 등. 노드 접미사 순서를 등장 순서로 착각하지 않는다.
- 텍스트 쌍: Delay 100.1 / 125.1 / 152.3 / 187.8 / 209.8 / 229.7이 각각 두 분기에서 반복된다. 쌍을 Merge로 조립하는 구조와 대응한다.
- 따라서 **기본 애니메이션, 등장 시점, 공간 배치를 분리해 반복 사용한다**는 해석이 가능하다. 사용자가 모든 작업에 고정 적용한다고 확인한 규칙은 아니므로 사례 기반 제안으로 유지한다.

TimeSpeed가 많다는 사실을 불필요한 노드나 병목의 증거로 보지 않는다. 최적화하려면 별도 측정이 필요하다. 다음 구현에서는 프리셋 내부 키 범위, Delay/Speed 이후 유효 소스 범위, 끝 프레임 유지 여부를 검증한다. 과거 매크로 뒷부분 잘림 문제가 자동 해결됐다고 주장하지 않는다.

## 다음 제작에 적용할 설계 규칙

1. **카메라에 포함할 장면 범위부터 정한다.** 함께 움직일 요소는 글로벌 체인 앞에서 합성하고, 고정할 요소만 뒤에 둔다.
2. 요소별 `Layout`, `LocalMotion`, 필요 시 `Timing`을 분리한다. 기존 애니메이션을 재사용할 때는 타이밍 조절 때문에 공간 배치를 다시 만들지 않도록 한다.
3. 합성 후 `Camera_Rotate`, `Camera_ZoomIn`, `Camera_Pan`, `Camera_ZoomOut`처럼 목적별 Transform을 둔다. 이는 새 노드의 권장 이름이며 현재 사용자 노드를 자동 개명하지 않는다.
4. '한 움직임 목적당 한 Transform'을 지향하되, 한 노드에 고정 Size/Pivot 보정까지 있는 실제 구조를 허용한다. 모든 속성을 무조건 노드 하나씩으로 쪼개지 않는다.
5. 카메라 이동은 단순한 장식 줌이 아니라 어떤 요소를 언제 보여줄지에 맞춰 설계한다. 구체적인 주목 대상은 사용자 대본/화면 근거로 결정한다.
6. 이동, 회전, 줌의 중첩과 홀드를 명시한다. 이번 f68/f123 등의 절대 프레임을 새 영상에 복사하지 않는다.
7. 합성된 캔버스의 도메인/해상도, 움직임 여유 영역, 회전 가장자리와 필터 품질을 확인한다. 여러 Transform을 한 노드로 합치면 순서·Pivot·키 편집성이 달라질 수 있으므로 임의 통합하지 않는다.
8. 검증은 키/연결 확인과 시각 확인을 분리한다. 이번 문서는 구조 분석 완료이며 렌더/움직임 체감 검증은 하지 않았다.

## 근거와 범위

[두 번째 그래프 근거](evidence/20260908_graph_structure_02.json): 연결, 스플라인 키와 프레임 63의 샘플 값. 사용자 요청에 따라 수식은 스타일 근거 파일에서 제외했다. 원본 미디어·텍스트 내용·로컬 미디어 경로는 포함하지 않는다. 파일은 불러올 수 있는 .comp가 아니며, 매크로 내부 연결만으로는 그룹 경계를 포함한 완전한 실행 그래프를 복원했다고 주장할 수 없다.

이번 관찰에서 공통으로 강화된 핵심은 **로컬 요소 → 합성 장면 → 글로벌 카메라라는 계층적 설계**다. 새로 관찰한 타이포 반복, Delay 기반 시간 배치, Pivot 선택은 이를 구현한 사례로 기록하고, 효과 종류 자체를 사용자 취향의 필수 조건으로 올리지 않는다.
